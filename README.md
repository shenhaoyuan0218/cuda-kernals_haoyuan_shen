# cuda-kernels

本人就读于宁波诺丁汉大学（UNNC）计算机科学专业，目前大一，正在自学 AI 基础设施（AI Infra）方向的 GPU 编程。

本仓库以《大规模并行处理器程序设计（原书第 4 版）》（PMPP）中译本为主线，按章节整理 CUDA 代码、课后练习和云端调试记录。每章围绕具体问题展开：程序中哪些工作可以并行？一个线程负责哪些数据？改变线程分工后，内存访问会怎样变化？

## 学习与实验安排

平时在 MacBook 上阅读教材、编写代码，并用小规模输入手算线程下标和预期结果。**每五周在阿里云 PAI-DSW 上集中进行一次 GPU 调试**，编译这一阶段积累的核函数，对照预期结果检查输出，记录发现的问题和修正过程。涉及性能比较时，同时记录 GPU 型号、输入规模、线程块配置和耗时。

**当前进度：已整理到第 3 章「多维网格和数据」。** 代码与笔记随章节更新，实测结果在对应轮次的云端调试后补充。

### 第 1 章导读 · 从一个 CPU 循环看数据并行

本章从计算任务本身入手。以向量加法 `C[i] = A[i] + B[i]` 为例，计算 `C[1]` 只需要 `A[1]` 和 `B[1]`，可以独立于 `C[0]` 进行。一个串行循环中，可能包含大量可以同时计算的输出元素。

| 教材位置 | 阅读重点 | 结合向量加法理解 |
|---|---|---|
| §1.1 异构并行计算 | CPU 和 GPU 如何协作？ | CPU 准备数据并发起计算，GPU 上的线程分别处理不同元素，结果随后可传回主机。 |
| §1.2–1.3 并行性与应用加速 | 哪部分工作可以并行？它对整个程序耗时有多大影响？ | 数组越长，可独立计算的元素越多。评价整个程序时，还要计入数据传输和核函数启动的开销。 |
| §1.4 并行编程中的挑战 | 如何检查任务拆分是否正确？ | 每个输出元素都应有线程负责，同时要处理数组长度不能被块大小整除的情况。第 2 章用线程索引和边界判断解决这个问题。 |

本章以概念为主。阅读时可对照下一章源码中的 CPU 函数 `vecAdd`，先从循环体判断各次迭代之间是否存在依赖。[向量加法源码](./01_vector_add/vector_add.cu)

### 第 2 章导读 · 从 `vecAdd` 到 `vecAddKernel`

这一章沿着同一个算式读两遍：先看 CPU 如何用循环遍历整个向量，再看 GPU 上的每个线程如何确定自己负责的元素。[CPU 与 CUDA 向量加法实现](./01_vector_add/vector_add.cu)

| 教材位置 | 代码中关注什么 | 要理解的问题 |
|---|---|---|
| §2.1–2.3 数据并行与向量加法 | `vecAdd` 中的循环，以及 `vecAddKernel` 中的逐元素加法 | 两种实现计算相同的 `C[i]`。CPU 通过循环改变 `i`，CUDA 核函数通过线程编号得到 `i`。 |
| §2.4 设备内存与数据传输 | `cudaMalloc`、`cudaMemcpy`、`cudaFree` | 哪些数组是输入，哪个数组是输出？申请显存时为什么传指针变量的地址？复制数据时为什么按字节计算大小？ |
| §2.5–2.6 核函数、线程与启动配置 | `blockIdx.x`、`blockDim.x`、`threadIdx.x` 和 `<<<...>>>` | `blockIdx.x * blockDim.x` 给出当前块的起点，加上块内编号便得到全局线程编号。`if (i < N)` 保证只有合法线程才访问数组。 |

**课后练习关注点：每个线程处理两个元素时，怎样确定下标？** 设每块有 4 个线程，块 0 负责下标 `0～7`。如果要求每个线程处理两个相邻元素，线程 1 负责 `2、3`；如果把这 8 个元素等分成前后两段，让每个线程在两段的相同位置各取一个，线程 1 负责 `1、5`。两种分工覆盖相同的数据，但对应的索引公式不同。

### 第 3 章导读 · 从二维线程坐标到数组下标

本章把第 2 章的一维映射扩展到二维。先沿 `y` 方向计算行号、沿 `x` 方向计算列号，再用 `row * width + col` 定位按行存储的元素。三个正文示例集中在同一份源码中，可按函数名定位。[第 3 章正文示例](./02_matrix_add_2d/matrix_add_2d.cu)

| 教材位置 | 核函数 | 一个有效线程完成的工作 |
|---|---|---|
| §3.2 图 3.4 · 彩色转灰度 | `colorToGrayscaleConversion` | 定位一个像素，连续读取 R、G、B 三个分量，加权计算后写出一个灰度值。 |
| §3.3 图 3.8 · 图像模糊 | `blurKernel` | 遍历当前像素周围的邻域，累加图像范围内的灰度值，再除以实际参与计算的像素数。 |
| §3.4 图 3.11 · 方阵乘法 | `matrixmulKernel` | 固定输出的行号和列号，计算左矩阵对应行与右矩阵对应列的点积，写入一个结果元素。 |

**课后练习关注点：单个线程连续写到哪里？相邻线程在同一步又写到哪里？** 对于按行存储的 `4 × 4` 输出矩阵，每线程算一行时，线程 0 依次写入下标 `0、1、2、3`，四个线程第一次写入的下标却是 `0、4、8、12`。改成每线程算一列，四个线程第一次写入的下标变为 `0、1、2、3`。这个例子说明了为什么分析 GPU 合并访存时，需要观察相邻线程在同一步访问的地址。[第 3 章课后练习答案与解析](./02_matrix_add_2d/PMPP第四版第3章课后练习答案与解析.md)

矩阵乘向量练习进一步改变了输出形状：方阵乘向量得到一个向量，每个线程取矩阵的一行与输入向量做点积，写出一个结果。[练习 2：矩阵乘向量](./02_matrix_add_2d/chapter03-ex02.cu)

## 第一次云端调试计划

- **向量加法**：选取不能被线程块大小整除的向量长度，检查最后一个块的边界判断，对照 CPU 与 GPU 的输出。
- **图像处理**：用已知 RGB 值的小图核对通道偏移，再分别验证角点、边缘和内部像素的模糊结果。
- **矩阵运算**：先用可手算的小矩阵核对方阵乘法和矩阵乘向量的结果，再扩大输入规模，比较不同线程分工的运行时间。
